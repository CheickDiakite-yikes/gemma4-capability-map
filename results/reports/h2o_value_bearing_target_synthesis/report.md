# H2o Value-Bearing Target Synthesis

Generated: `2026-05-12T21:06:31.132485+00:00`

## Summary

H2o turns the H2n no-op/blocking policy into selective canonical target-query construction. When a longer value-bearing visual label is recoverable from the image-state catalog and the prompt evidence asks for that value-bearing component, the controller rewrites the model's shorter or reordered target query to the canonical layout label. This repairs the main H2m strict failures: H2o reaches 7/8 strict and executor-equivalent, compared with 3/8 strict for H2j and H2n. The transfer gates stay saturated on H2k, H2l, and H2f. The remaining H2m miss is a different problem: contextual surface-type alias routing, where the prompt says a tile-style result surface should target `result tile` but the model keeps the value `Blocked`.
